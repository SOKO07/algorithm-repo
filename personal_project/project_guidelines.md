# 프로젝트 가이드라인

이 프로젝트(충돌 회피 알고리즘 비교: APF · Bug2 · DWA)에서 작업하는 AI의 지침이다.
작업을 시작하기 전에 이 문서와 `ROADMAP.md`를 먼저 읽는다.

## 1. 방향은 `ROADMAP.md`가 정한다

- 무엇을 할지, 언제까지 할지는 `ROADMAP.md`를 따른다.
- 실험 설계(랜덤 지도, 지도당 1회 실행, 시드 분리, 풀이 가능성 검사, 짝 비교)가
  바뀌면 `ROADMAP.md`부터 고친다. 코드가 먼저 바뀌고 문서가 뒤처지지 않게 한다.
- 일을 끝내면 `ROADMAP.md`의 체크박스를 갱신한다.
- 로드맵에 없는 큰 변경(알고리즘 교체, 지표 변경, 지도 규칙 변경)은 임의로
  하지 않고 먼저 사용자에게 묻는다.

## 2. 과제 요구는 `raw/project-2026.mdx`를 기준으로 한다

모든 작업에서 이 문서의 요구와 평가 기준을 염두에 둔다.

- **필수:** 같은 문제를 푸는 기존 방식 셋 이상을 직접 돌려 **같은 조건**에서 비교한다.
  기준은 둘 이상, 수치로 잰다.
- **평가 다섯 가지:** 돌아가는 코드 · 측정(다시 얻을 수 있는 숫자) ·
  해석(이론과 이어서 설명) · 정리(본인 판단의 장단점·발전 방향) ·
  문서(남이 그대로 돌려 볼 수 있는가).
- **이론과 실측의 어긋남을 찾는다.** 어긋남을 찾아 설명하는 것이 좋은 보고서다.
- **최종 보고서 목차:** ① 주제와 동기 ② 방식 셋의 설명(원리, 의사코드/핵심 코드)
  ③ 비교 기준과 실험 설계 ④ 실험 결과(표·그래프·캡처) ⑤ 해석 ⑥ 장단점
  ⑦ 발전 방향 ⑧ 참고 자료와 **AI 사용 내역**.
- **규칙:** 남의 코드를 쓰면 출처와 수정한 부분을 밝힌다. AI에게 무엇을
  물었고 무엇을 받았는지 기록한다. 저장소는 공개되므로 개인정보를 넣지 않는다.
- **마감:** 최종 제출 2026-12-13 23:59 (LearnUs). 보고서 PDF 5~20장, 첫 장에 저장소 URL.

## 3. 작업할 때마다 `final_report.md`에 기록한다

나중에 보고서를 쓰기 쉽도록, 작업을 끝낼 때마다 `final_report.md`에 해당
보고서 목차 번호 아래로 내용을 덧붙인다. 보고서 문장 그대로 쓸 수 있는 수준으로 적는다.

기록할 것:

- **무엇을, 왜 그렇게 했는가.** 설계 결정과 대안, 선택 이유 (예: Bug2를 연속 공간으로 구현한 이유).
- **파라미터와 설정값.** 값과 정한 근거(튜닝 시드에서 정했는지).
- **측정 결과와 관찰.** 숫자, 이상한 점, 예상과 달랐던 점, 실패 사례.
- **어긋남과 한계.** 이론 기대와 실측이 다른 곳, 가정 때문에 생기는 한계.
- **출처.** 참고한 논문·문서·남의 코드와 고친 부분.
- **AI 사용 내역.** 무엇을 AI에게 맡겼고 어떤 결과를 받았는지 (8번 항목에 모은다).

형식 규칙:

- 날짜와 작업 이름이 있는 항목으로 쌓되, 목차(①~⑧) 아래에 분류해 둔다.
- 결과 그래프·캡처는 파일 경로를 적어 둔다. 숫자는 CSV 출처를 함께 적는다.
- 확인하지 못한 것은 확인한 것처럼 쓰지 않고 "미확인"으로 표시한다.

## 4. 진행 방법을 `README.md`에 적는다

읽는 사람이 **그대로 따라 하면 재현되도록** 코드 진행 방법을 그때그때 `README.md`에 적는다.

- 환경(Python 버전, 필요한 라이브러리와 설치 방법), 실행 명령을 순서대로 적는다.
  명령은 그대로 복사해 실행할 수 있게 코드 블록에 둔다.
- 새 스크립트나 단계를 추가하면 같은 작업 안에서 README도 갱신한다.
- 다룰 내용: 지도 생성, 알고리즘 실행, 튜닝 시드와 평가 시드, 결과 CSV 생성,
  요약·그래프 생성, 테스트 실행.
- README는 "어떻게 돌리는가"만 담는다. 이유와 해석은 `final_report.md`에 쓴다.
- 문서에 적은 명령은 실제로 실행해 보고 적는다. 실행하지 않은 명령은 적지 않는다.

## 5. 재현성 규칙

- 모든 무작위 요소는 시드로 고정한다. 튜닝 시드(0~49)와 평가 시드(1000~1299)는
  섞지 않는다. **평가 결과를 보고 파라미터를 바꾸지 않는다.**
- 확정한 파라미터는 코드나 설정 파일 한 곳에 모아 기록한다.
- 풀 수 없어서 버린 지도 수를 기록한다.
- 원시 실행 결과는 CSV로 저장하고, 요약은 스크립트로 만든다. 숫자를 손으로 옮기지 않는다.

## 6. 작업 습관

- 작업을 마치면 `ROADMAP.md` 체크, `final_report.md` 기록, `README.md` 갱신을 한 묶음으로 처리한다.
- 코드는 테스트(`tests/`)로 확인한다. 알고리즘 구현 전에 시뮬레이터가 맞는지 먼저 확인한다.
- 커밋은 사용자가 요청할 때만 한다. 한 커밋에는 한 가지 주제만 담는다.
- `.work/`(개인 작업 폴더)와 개인정보는 커밋하지 않는다.
- 이 저장소의 `CLAUDE.md`와 `AGENTS.md`는 교수님의 template 관리용이며 이 프로젝트에 적용하지 않는다.
