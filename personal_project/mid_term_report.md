## 2장. 주제와 선정 이유

### 고른 주제
2차원 평면 시뮬레이션에서 이동체가 장애물을 피하면서 목적지에 도달하도록 하는 충돌 회피 방법을 비교한다.

### 고른 이유
- 자율주행차나 이동 로봇이 안전하게 움직이려면 목적지에 도달하는 것과 함께 장애물을 피하는 능력도 필요하다.
- 충돌 회피 방식에 따라 안전성이나 이동 효율이 달라질 수 있어, 어떤 상황에서 각 방식이 유리한지 알아보고 싶었다.
- 장애물 배치가 달라질 때 알고리즘의 움직임과 장단점이 어떻게 달라지는지 시각적으로 확인할 수 있는 주제다.

---

## 3장. 풀려는 문제

> **장애물이 있는 2차원 환경에서 이동체가 장애물과 충돌하지 않고 출발점에서 목적지까지 도달할 수 있을까?**

### 연구 가설
- 각 알고리즘은 안전성, 도착 성공률, 이동 거리와 계산량에서 서로 다른 장단점을 보일 것이다.
- 장애물이 복잡하거나 좁은 통로가 있을 때 알고리즘별 성능 차이가 커질 것이다.

---

## 4장. 비교 방식 ① 인공 포텐셜 필드 (APF)

### 핵심 아이디어
목적지는 이동체를 끌어당기는 힘으로, 장애물은 밀어내는 힘으로 표현한다. 두 힘을 합한 방향으로 조금씩 이동한다.

### 장점과 한계
- 구현이 비교적 간단하고 매 단계의 계산이 가볍다.
- 장애물 주변을 자연스럽게 피하는 움직임을 만들 수 있다.
- 힘이 서로 상쇄되는 지점에 멈추는 지역 최소 문제로 목적지에 도달하지 못할 수 있다.

### 비교 방법
APF에도 7장의 공통 지표를 동일하게 적용한다. 포텐셜 힘의 크기 등 내부 계산값은 성능 비교 지표로 사용하지 않는다.

---

## 5장. 비교 방식 ② Bug2

### 핵심 아이디어
목표 방향으로 이동하다 장애물을 만나면 장애물 경계를 따라 이동한다. 시작점과 목표점을 잇는 선에 다시 도달하면 목표 방향으로 진행한다.

### 장점과 한계
- 규칙이 명확해 구현과 동작 설명이 쉽다.
- 장애물 경계를 이용해 막힌 상황에서 우회할 수 있다.
- 경계를 따라가는 경로가 길어질 수 있고, 센서와 접촉 판정 가정에 결과가 영향을 받는다.

### 비교 방법
Bug2에도 7장의 공통 지표를 동일하게 적용한다. 경계 추종 단계 수는 필요할 때 동작 분석용 보조 기록으로만 남긴다.

---

## 6장. 비교 방식 ③ 동적 창 접근법 (DWA)

### 핵심 아이디어
이동체가 낼 수 있는 속도와 회전 속도 후보를 짧은 시간 동안 시뮬레이션한다. 장애물과의 거리, 목표 방향, 진행 속도를 점수화해 가장 적절한 움직임을 고른다.

### 장점과 한계
- 이동체의 운동 제약과 주변 장애물을 고려해 매 순간 움직임을 선택한다.
- 동적 장애물 회피로 확장할 수 있다.
- 후보 속도와 시뮬레이션 시간을 정해야 해 APF보다 계산량과 설정이 많다.

### 비교 방법
DWA에도 7장의 공통 지표를 동일하게 적용한다. 속도 명령은 필요할 때 동작 분석용 보조 기록으로만 남긴다.

---

## 7장. 비교 기준과 측정 방법

### 세 알고리즘에 공통으로 적용할 지표
- **충돌률:** 충돌한 실행 횟수 ÷ 전체 실행 횟수.
- **도착률:** 목표에 도달한 실행 횟수 ÷ 전체 실행 횟수.
- **이동 거리:** 이동체 중심점이 이동한 전체 거리.
- **이동 단계 수:** 시뮬레이션에서 이동 명령을 적용한 횟수.
- **계산 시간:** 알고리즘이 이동 명령을 계산하는 데 걸린 누적 시간. 시각화 시간은 제외한다.

모든 알고리즘을 같은 지도·출발점·목적지에서 같은 횟수만큼 실행한다. 결과 표에는 위 공통 지표만 사용하고, 알고리즘별 내부 동작값은 별도 분석에만 활용한다.

### 충돌 판정
이동체의 원형 몸체가 장애물 영역과 겹치면 충돌로 판정한다. 세 알고리즘에서 이동체 크기와 충돌 여유 거리를 동일하게 둔다.

### 해석 원칙
안전성을 우선해 충돌률과 도착률을 먼저 비교한다. 이동 거리나 계산 시간이 짧더라도 충돌률이 높으면 더 나은 방법으로 단정하지 않는다.

## 8장. 실험 설계

### 입력 환경
- 2차원 시뮬레이션 지도에 출발점, 목표점, 원형 또는 격자형 장애물을 배치한다.
- **지도 유형**은 환경의 큰 구조를 뜻한다. 예를 들어 열린 공간, 장애물이 많은 공간, 좁은 통로가 있는 공간으로 나눈다.
- **장애물 배치**는 같은 유형 안에서 장애물의 위치와 모양을 달리한 개별 지도다. 유형별로 서로 다른 배치 5개를 만든다.
- 총 3개 유형 × 유형별 5개 배치 = **서로 다른 지도 15개**를 사용한다. 지도와 난수 시드를 공개해 재현 가능하게 한다.

### 규모와 반복
- 지도 유형: 3종
- 유형별 장애물 배치: 5개 (총 15개 지도)
- 알고리즘: 3개 (APF, Bug2, DWA)
- 각 지도에서 알고리즘별 실행: 1회
- 전체 실행: `15개 지도 × 3개 알고리즘 = 45회`

같은 지도와 설정에서 무작위 요소 없이 실행하면 성공 여부, 이동 거리, 이동 단계 수는 매번 같으므로 이 값들은 한 번 기록한다. 계산 시간만 실행 환경에 따라 달라질 수 있으므로 같은 조건에서 5회 측정하고 중앙값을 기록한다.

### 통제 요소
시뮬레이션 크기, 이동체 크기, 속도 제한, 시작·목표 위치, 충돌 판정, 최대 이동 단계 수를 동일하게 적용한다. 본 실험에 쓰지 않는 소수의 시험 지도에서 각 알고리즘의 설정값을 먼저 조정하고, 확정한 값은 기록해 둔다. 이후 15개 평가 지도에서는 결과를 보고 설정값을 바꾸지 않는다.

## 9장. 실험 절차와 결과 기록

1. 시뮬레이션 지도와 이동체의 움직임·충돌 판정을 구현한다.
2. APF, Bug2, DWA를 같은 인터페이스로 구현한다.
3. 파일럿 환경에서 각 알고리즘의 파라미터와 최대 실행 단계를 정한다.
4. 지도별로 모든 알고리즘을 같은 환경에서 실행하고, 지도와 실행 순서를 섞는다.
5. 성공·충돌 여부, 거리, 이동 단계 수는 한 번 기록하고, 계산 시간은 같은 조건에서 5회 측정해 중앙값을 CSV에 저장한다.

## 10장. 비용·재현성·한계

### 비용 관리
- 실제 장비나 유료 API 없이 로컬 시뮬레이션으로 실험한다.
- 지도 수와 반복 수를 먼저 파일럿으로 확인한 뒤 고정한다.
- 최대 이동 단계 수를 두어 무한 루프나 지나치게 긴 실행을 막는다.

### 재현성
- 코드, 지도 생성 규칙, 난수 시드, 알고리즘 파라미터, 실행 환경을 공개 저장소에 기록한다.
- 원시 실행 결과 CSV와 결과 요약 스크립트를 함께 보관한다.
- 동일한 지도와 설정으로 다시 실행할 수 있도록 버전을 관리한다.

### 한계
- 2차원 시뮬레이션 결과가 실제 장치의 센서 오차나 물리적 움직임을 완전히 반영하지는 않는다.
- APF, Bug2, DWA는 접근 방식과 가정이 달라 파라미터 설정에 따라 순위가 달라질 수 있다.
- 지도 유형과 장애물 수가 제한되면 다른 환경에 일반화하기 어렵다.
- 정적 장애물을 우선 다루며, 움직이는 장애물은 후속 실험으로 남긴다.

### 결론 판단 기준
충돌률이 낮고 도착률이 높은 방법을 우선 평가하고, 이동 거리와 계산 시간으로 효율의 차이를 설명한다.
